# Stage05 engine algorithm and trust boundary

Pure TypeScript state transitions take explicit versioned rules, actor seat, command, instant and bounded random source. No database/network/clock is imported by the engine. A separate adapter supplies unbiased crypto.randomInt. Rules and initial shuffled deck are private replay inputs; no default product rule profile is enabled. See05-rule-decisions.md for pending choices.

Create: validate rules -> construct unique physical cards -> unbiased Fisher-Yates -> alternate deal -> choose a plain opening card -> persist active seat/version/deadline. Every accepted transition preserves the exact multiset of card identities across both hands, market and discard. Forfeit/timeout/terminal draw keep cards for private replay. Compatibility, pending penalties and draw-then-play eligibility are computed on the server.

Command: validate bounded ID/version/input -> recognize identical action replay (changed payload conflicts) -> reject terminal/wrong seat/stale version/backdated/expired action -> clone state -> check card ownership/legality or draw/pass -> apply declared rule effects -> check terminal outcome/bounds -> increment version and set next deadline -> return immutable private state and redacted projected view. Client commands never include timeout or a winner. Server timeout uses a separate entry point and the same expected-version/deadline boundary, so an action and timer cannot both win.

Each reshuffle records bounded random choices for deterministic command replay. Initial private snapshot plus accepted command/instant/random choices must rebuild the same final state. Bot decisions consume only a projected own-hand view and legal action descriptors; they cannot inspect opponent cards or deck order. Scheduling bot latency belongs to a later server worker, never a blocking sleep in the engine.

Persistence uses new game_matches/game_players/game_events tables to avoid repurposing legacy per-player match rows before settlement migration. A transaction row-locks the match, deduplicates action identity and payload, maps an authenticated canonical player to its stored seat, applies the pure engine, writes private snapshot/event and a redacted outbox notification, then commits. No Redis/socket state is published before commit. This is internal persistence, not an admission/quota API; no public game endpoint is enabled by stage05. All later outward reads must use projection for the authenticated stored participant.

Validate malformed cards/commands/rules, conservation, special effects and both supported draw/stack policies, no hidden data in projection, replay, duplicate/version/timeout races, bot-view isolation and10000 bounded simulated games. Use PostgreSQL18 for exact two-seat/mode constraints and atomic event/snapshot/outbox rollback. Product decisions and hosted recovery remain explicit open acceptance gates.
