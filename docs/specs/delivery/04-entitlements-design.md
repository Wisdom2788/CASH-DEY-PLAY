# Entitlement, daily task and attribution implementation design

25 October 2026. Implement only server-verifiable eligibility. Stars, ad callbacks, ranked settlement and referral qualification remain their owning stages.

Premium derives exclusively from explicit entitlement contributions with source PAID_ORDER and a verified payment reference, starts_at <= evaluation instant < expires_at, and no revocation. Legacy user/subscription flags are revoked at migration and never consulted. Preserve old grants as historical rows; do not infer a paid purchase from them. Ad-free days are a separate source valid until their stored Lagos midnight boundary and never grant premium tier or unlimited practice.

Task state uses the database evaluation instant after acquiring a per-player row lock. Date derives from Africa/Lagos at that instant. All writers lock the player row first, then daily rows; parallel completions serialize. Two video tasks are AUTO_READY only while current premium or ad-free eligibility applies. Expiry/refund between reading and claiming must be rechecked. A claim inserts its unique claim record, transitions task state, adds exactly50 points, and mirrors canonical completion in one transaction. Normal ad claims and ranked-win client claims remain unavailable. All-complete is awarded automatically once when the other three are CLAIMED under that same lock. Migration maps recognized historic task records to CLAIMED without adding points; optional-video rows never become a complete task day. Public state retains compatibility fields but reports unavailable gameplay allowance as unavailable, not invented capacity.

First-login signed attribution intent stays atomic with account creation. Generate8-character codes with crypto randomness; retry unique-code collisions inside savepoints, bounded to8 attempts. Existing deterministic codes are retained for old links; new users never receive Telegram-ID-based codes. Resolution locks one unresolved intent, finds the canonical referrer, rejects self/unknown/expired attribution, inserts at most one referred-player link, and marks the intent resolved in one transaction. Resolution failure never rolls back an already completed login; unresolved intents can be retried by a private command. Referral window ends30 elapsed days after first creation. No referral points are issued at this stage. Link generation requires configured Telegram bot and Mini App names; unavailable configuration returns no fictitious link.

Tests must use PostgreSQL18 and cover exact expiry, stale auto-ready state, premium/ad-free overlap, concurrent claims/bonus, rollback, legacy non-reaward, concurrent intent resolution, late links, unknown/self links and forced random-code collision. Public APIs authenticate current registered identity and reject client-supplied source evidence. Deployment follows the existing backup/restore and migration gates.
